# Структура і простежуваність (архітектура з ЛР №4)

Підстава: вимоги ЛР №1, діаграми класів і компонентів ЛР №2 та перший спринт ЛР №3. Моноліт Django із серверними шаблонами та SQLite; стандартна модель користувача Django, без власного класу `User`. Класи `ShortLink`, `LinkForm`, `CodeGenerator`, `LinkService`, `RedirectService` відповідають діаграмі ЛР №2; взаємодія зі сховищем реалізована Django ORM, а не дубльованим класом-обгорткою `LinkRepository`.

| Вимоги | Реалізація |
| --- | --- |
| FR-01, FR-02, NFR-02 | Django Auth, `RegistrationForm`, маршрути `/register/`, `/login/`, `/logout/`; паролі хешуються Django |
| FR-03, NFR-03 | `LinkForm`, `LinkService.create`, `/links/new/` з перевіркою HTTP/HTTPS |
| FR-04 | `CodeGenerator`, `UNIQUE` на `code`, обмежене повторення після колізії |
| FR-05, FR-08 | `RedirectService`, `F()` для атомарного інкременту, HTTP 302 або 404 |
| FR-06, FR-07, NFR-06 | `list_for` і `delete_for` з фільтром за власником; POST і CSRF для видалення |
| FR-09 | Стандартна Django Admin |
| NFR-07 | SQLite і міграція; для реального розгортання потрібен постійний диск |
| NFR-01, NFR-04, NFR-05 | Архітектурні передумови й конфігурація HTTPS; навантажувальні та кросбраузерні випробування не проведено |

SRP: форма перевіряє ввід, сервіс виконує бізнес-операцію, view керує HTTP, модель описує дані. DIP/OCP у генерації коду: `LinkService` приймає альтернативний генератор через конструктор (використано в тестах). Не створюємо зайвих абстракцій лише заради формального SOLID.

Перший спринт ЛР №3: A-01 і A-02 та основа FR-01—FR-04/NFR-02/NFR-03; мінімальні FR-05—FR-09 додано як каркас сценаріїв архітектури ЛР №2. Це код лабораторної, а не підтвердження завершення запланованого двотижневого спринту.

Git: у разі командної роботи — окрема гілка `feature/<назва>` на задачу, pull request, перегляд змін іншою людиною перед злиттям у `main`. Наразі розробник один, тому реального командного review не було; не слід видавати його за проведений.

Для ЛР №5 актуальні результати інтеграції, нові тести й невиконані зовнішні перевірки описано в [`integration.md`](integration.md); цей документ зберігає архітектурні рішення попереднього етапу.
